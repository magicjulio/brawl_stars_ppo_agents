# 04 — Headless `libg.so` battle-sim design (for fast offline RL)

Date: 2026-10-06. Status: **Phase 0b done (static analysis); Phase 1 blocked on substrate + v2x APK.**
Plan of record: `~/.claude/plans/fuzzy-tickling-tide.md`. Supersedes the gadget-client route in `03`.

## Goal recap
Train an RL agent to beat the game's bots, **fully offline**, observations read from the **real game's
memory**. Approach: drive the deterministic, headless `LogicBattleModeServer` tick loop directly (no
rendering, no UI, no 20 Hz cap), one battle per process, scaled across ARM cores. No networking path at
all → offline by construction.

## Version strategy (decided)
- **Runtime target: a pre-Arxan v2x build (v26–v29 band).** Arxan packing entered at **v30**, so v29 and
  below have a normal `R-E .text` (no decrypt-on-fault) and clear anti-tamper with a small hook set.
  - **v27** — open-source offline-bot server (Classic Brawl 27) → best battle-init reference.
  - **v29** — matches our existing frida bypass recipe (`scratchpad/v29ref/liberder.script.js`).
  - Tie-break = **symbol richness** of the candidate `libg.so` (run `tools/extract_offsets.py` on it).
- **Analysis oracle: v36.218 (the APK we have).** Uniquely ships a rich `.symtab` (41,336 named FUNCs).
  Its DWARF is only FreeType/vendored libs — **not** Logic — so struct layouts come from disassembling
  the named accessors, not from DWARF. v36 is the dictionary we map onto the chosen v2x runtime binary.
- No benefit to going older than ~v26: Arxan is already absent, and name/offset drift from the v36
  dictionary only grows.

## Feasibility — confirmed by inspection of v36 `libg.so`
- **It's a clean, named, server-side sim.** `LogicBattleModeServer` exposes the whole battle lifecycle;
  the `Logic*` layer is deterministic C++ over CSV data tables (the same code Supercell runs server-side).
- **Game data is plaintext CSV in the APK** (`assets/csv_logic/*.csv`: `globals.csv`, characters, …),
  loaded via `LogicDataTable::loadTable(CSVTable*)` / `LogicGlobals(CSVTable*,int)`.
- **Constraints (version-invariant):** ELF32 **ARM**; needs a bionic/Android host
  (`DT_NEEDED`: liblog, libandroid, libEGL/GLESv3, libfmod, libc, …); `JNI_OnLoad` present; the Logic
  symbols are `LOCAL HIDDEN` → callable only **by address, in-process** (frida on native ARM). This is
  why a real ARM CPU is required (the x86 emulator's ndk_translation made libg.so un-instrumentable).

## Function inventory (v36 reference addresses → `docs/offsets.v36.json`)
Generated by `tools/extract_offsets.py`. Addresses are **v36**; re-run the tool on the chosen v2x binary
for its addresses (names are expected to match; verify).

Battle lifecycle (`LogicBattleModeServer::`):
- `executeOneTick(LogicArrayList<BitStream*>*, BitStream*)` @ `0x8a26d8` — the per-tick driver.
- `addGameObjects(...)` @ `0x3274e4`, `addPlayer(...)` @ `0x70b558`, `spawnHero(...)` @ `0x4454c8`.
- `setBotDifficulty(int)` @ `0x292104`, `setRandomSeed(int)` @ `0x5d8398` (reproducibility),
  `generateTileMap(int,int,int)` @ `0x84d504`, `setLocation(...)` @ `0x3aabe8`.
- Reward/termination: `getTeamScore(int,bool)` @ `0x513c88`, `getCurrentMVP()` @ `0x4dd6b8`,
  `forceGameOver()` @ `0x7bf9d8`, `tickUpdate(int)` @ `0x1304b0`.
- Player input path: `handleClientInput(ClientInput*,int)` @ `0x75c168`.

Action / command encoding (`LogicCommandManager::`): `createCommand(int)`, `addCommand(...)`,
`encodeCommand/decodeCommand`, `save/loadCommandFromJSON` (JSON path validates our action round-trips).

## Observation map (struct field offsets, auto-derived from v36 accessors)
Method: each const getter compiles to a `this`(r0)-relative load; the immediate is the field offset.
**These offsets are v36** — re-derive on the v2x runtime binary (same tool). HP field is best confirmed
dynamically.

| Field | Accessor | Class | v36 offset |
|---|---|---|---|
| position | `getPosition()` | LogicGameObjectServer | `+0x1c` |
| x / y | `getX()` / `getY()` | LogicGameObjectServer | `+0x1c` / `+0x20` |
| tileX / tileY | `getTileX()` / `getTileY()` | LogicGameObjectServer | `+0x1c` / `+0x20` |
| globalID | `getGlobalID()` | LogicGameObjectServer | `+0x4` |
| state | `getState()` | LogicCharacterServer | `+0x64` |
| isMoving | `isMoving()` | LogicCharacterServer | `+0x14` |
| botSkill | `getBotSkill()` | LogicCharacterServer | `+0xb8` |
| maxHealth | `setMaxHealth(int)` (writer) | LogicCharacterServer | `+0x90` |

Still to map (Phase 0b/1, on the runtime binary, dynamic-verify): current hitpoints (from `causeDamage`
@ `0x6f8088` / `heal` @ `0x11bcf8`), team/owner (via `getPlayer()` @ `0x670364`), ammo/super charge.

## Open engineering items (resolve during Phase 1 bring-up)
1. **Data-load path & minimum boot prefix.** Which calls populate `LogicDataTables` from
   `assets/csv_logic`, and how far the app must boot to reach "tables loaded" without starting the render
   thread. Options: (a) let it boot that far then hijack; (b) call the loaders directly. (Classic Brawl
   27's offline-battle code is the reference for the init order.)
2. **Guard neutralization on native ARM** — small hook set (see `03`); expected easy pre-Arxan.
3. **Action encoding** — build move/aim/attack/super via `LogicCommandManager` → `BitStream` →
   `executeOneTick`; validate with `saveCommandToJSON`.
4. **Battle construction sequence** — `addPlayer`/`addGameObjects`/`spawnHero`/`setBotDifficulty`/
   `setRandomSeed` ordering for a 1v1(bot) battle; confirm a bot acts and score/`forceGameOver` behave.

## Tooling
- `tools/extract_offsets.py` — symtab inventory + leaf-accessor offset extraction (readelf + c++filt +
  llvm-objdump). Reusable; run on the chosen v2x binary. (GNU objdump here lacks ARM → use llvm-objdump.)
- `docs/offsets.v36.json` — generated v36 reference inventory.

## Prerequisites to start Phase 1 (both user-side)
1. **A rooted ARM Android device** (ADB-reachable) — the substrate for all phases.
2. **A pre-Arxan v2x APK** (v27 preferred, v29 fallback) — the runtime binary.

## Hard constraints (unchanged)
Fully offline; never contact public Supercell servers (no network path exists here); research only; our
own authentic APK; do not run untrusted third-party client binaries.
